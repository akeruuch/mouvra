# Как читать код MOUVRA

Начни с формы регистрации в `components/ui.tsx`: найди функцию `AuthDialog`.
Затем открой `authenticate` и `api` в `components/store.tsx`.
Для PHP-версии продолжи в `backend/src/api.php`, затем в `backend/src/auth.php`.
Так ты пройдёшь весь путь запроса от кнопки до базы данных.

## Как проходит регистрация

1. Пользователь вводит поля в `AuthDialog` и нажимает кнопку.
2. `submit` отменяет обычную перезагрузку формы через `preventDefault()`.
3. `FormData` собирает значения полей. Атрибут `name` задаёт ключ каждого значения.
4. `s.authenticate('register', data)` передаёт их функции `api`.
5. `api` отправляет `POST /api/register` с телом JSON.
6. PHP в `backend/src/api.php` проверяет запрос и вызывает `authenticate` из `auth.php`.
7. Сервер проверяет имя, email и пароль. При ошибке возвращает сообщение и HTTP-статус.
8. Если проверки пройдены, сервер создаёт пользователя, хеширует пароль и создаёт сессию.
9. Браузер получает cookie сессии и JSON с публичными данными пользователя.
10. `store.tsx` обновляет состояние. React показывает пользователю результат.

Сейчас регистрация возвращает первую найденную ошибку. Поле возраста и сбор всех
ошибок из лекции №10 ещё не добавлены: изменение оформления кода не добавляет эти возможности.

## Как читать API

Один и тот же адрес может выполнять разные действия в зависимости от метода:

| Запрос                           | Действие                        |
| -------------------------------- | ------------------------------- |
| `POST /api/register`             | Создать аккаунт                 |
| `POST /api/login`                | Войти                           |
| `GET /api/account`               | Получить данные своего кабинета |
| `PUT /api/state`                 | Сохранить корзину и избранное   |
| `GET /api/reviews?productId=...` | Получить отзывы товара          |
| `POST /api/reviews`              | Создать отзыв                   |
| `PATCH /api/reviews/ID`          | Изменить свой отзыв             |
| `DELETE /api/reviews/ID`         | Удалить свой отзыв              |

`200` — запрос выполнен; `201` — запись создана; `400` — неверные данные;
`401` — нужен вход; `403` — запрос запрещён; `404` — запись/адрес не найдены;
`409` — конфликт, например повторный отзыв; `503` — сервис временно недоступен.

## Почему есть ещё lib/account.ts

У проекта два серверных варианта, а также статическая демонстрация:

- **PHP + MySQL:** обработчики находятся в `backend/src`, запуск описан в README через Docker.
- **Cloudflare D1:** маршруты находятся в `app/api`, общая логика — в `lib/account.ts`, таблицы — в `db/schema.ts` и `drizzle`.
- **GitHub Pages:** работает интерфейс и локальный демонстрационный кабинет; PHP и настоящая регистрация здесь не выполняются.

Это альтернативные режимы запуска. PHP не вызывает `lib/account.ts`.
Когда меняешь правила регистрации, проверяй оба серверных варианта, если они должны вести себя одинаково.

## Где менять поведение

Добавить поле: `AuthDialog`. Проверить его на сервере: `backend/src/auth.php`
и соответствующий участок `lib/account.ts`. Изменить внешний вид: CSS.
Изменить правила отзывов: `Reviews.tsx` для интерфейса и API для серверных проверок.

Для проверки TypeScript используй `npm run typecheck`, для имеющихся тестов — `npm test`.
`npm run test:php` требует работающего PHP/MySQL-сервера. Сборка интерфейса:
`npm run build:php` или `npm run build:pages`, в зависимости от режима.
